Tekon Web 发起与运行控制设计

2026-09-07 · v0.25.0 · 产品范围 · 运行时合同 · 操作手册

1. 页面与信息责任

默认 Sessions 列表和 Session 详情提供受控交付发起、feed、审批和原 Run 控制；Advanced 下的 Runs 列表和 Run 详情保留运行与证据视角。Approvals、Delivery、Config、Eval 四个页面分别承载审批、远端动作、配置和质量判断。相同运行的控制共用 RunControls，Run/Session 恢复提示以同一服务端快照为准。

用户应能判断三件事：请求是否被受理、运行当前实际状态、下一步能做什么。按钮回执、领域状态和进程退出证据分别呈现，不用 Toast 推导执行已经开始或已停止。

2. 发起与不确定结果

默认与高级入口都展示模板/模式、Provider、风险和逐项检查来源/行为；高级项容纳 Profile、超时和动态预览。缺少 digest 或配置无效时阻止提交并提供刷新/修复入口。刷新后比较新旧检查结果并展示差异，由用户再次确认；原始命令和敏感环境不放进公开预览。

提交前写当前标签页的请求账本；请求发出后、受理结果返回前禁止重复提交。网络错误保留 Request ID，查询原请求或同意图重试；not-found 只表示本次查询未找到记录，不等于请求未受理，因此不更换 Request ID。只有明确另建任务时才生成新的 Request ID。已受理的回执不会被账本、查询或导航失败覆盖，始终提供“观察原会话/运行”；目录未就绪时显示已受理且尚未执行，给出修复后重试原请求的路径。

凭据与 Provider 分开显示：凭据有效不等于 Provider 可执行。Provider 有检查时间、检查中/可用/不可用/失败与重试入口；失败后的旧时间不冒充本次成功。切换物理仓库/凭据作用域清除不属于当前上下文的展示。

3. 运行控制与反馈

动作 确认与成功反馈 随后观察
暂停 单次提交；“暂停请求已记录，活动步骤将在边界停下” 当前步骤可能继续；查看原 Run 状态与节点进度
恢复 必要时先检查旧执行并确认旧 Job；“已受理恢复，请观察原运行” 复用原 queued Job 或新代 Job 都只是受理；观察原 Run，勿另建任务
取消 点取消后 3 秒内再次点“确认取消？”；成功后反馈“取消已记录” 取消已记录不代表受管理句柄全退出；已先 passed/failed 的运行保留原终态
重试取消 投递/观察待恢复时在原 Run/Session 保留入口 重新查询持久状态和退出证据，不制造新 Run
审批后恢复 展示证据与人工批准 可分别出现“审批已记录、运行尚未恢复”，继续处理原运行

初始排队任务被暂停后，若恢复发生在 Job 被认领之前，可沿用原 Job；若暂停期间 Job 已排空，恢复时创建新的执行 Job。界面不承诺具体 Job 是否已开始，事务竞争由服务端决定。已存在活动 Job、终态竞争、未确认退出或过期确认都显示真实反馈，不显示成功提示替代错误。

恢复确认绑定服务端快照中的 previousJobId；刷新后若出现新一代 Job，必须重新检查并确认该 Job。没有历史 Job 的情况由服务端表达，不由浏览器猜测。人工确认仅记录检查行为，物理退出证据仍以管理句柄为范围。

4. 观察、错误与可访问性

Session feed 是可实时刷新的观察投影，首连/重连与治理事件触发最新状态读取；旧响应不能覆盖新状态。模型逐块流式输出、follow-up 和 steer 暂未开放。Advanced 页面在控制操作完成后会自动读取一次状态；要持续查看后续进展，仍需手动刷新或重新进入页面。这次自动读取不等于持续实时订阅。

请求中禁用对应重复动作；错误保留可见，提供下一步而不只闪过通知。终态反馈在控制按钮消失后仍应可读。通知使用常驻 Live Region，状态/错误不只靠颜色表达。键盘可以触达控制、确认与观察入口，焦点样式清晰；长错误、长身份和按钮文字可换行，不遮挡主要内容。

窄屏检查行允许标签与证据分行，证据静态完整换行，触摸、悬停与键盘聚焦均不依赖超出卡片的提示浮层。长证据链接在卡片内换行；主内容允许收缩，侧栏显示时也不撑出页面。Runs 表格保留局部横向滚动与完整操作列。

主要验证视口为 320/390/768/1440px，另检查 600/601/769px 断点边界；覆盖上述主要页面、错误/请求中/终态/确认状态、取消二次确认及恢复跳转，检查横溢、裁切、重叠和键盘操作。几何检查同时验证文本自身与卡片边界，不能仅用整页宽度判断内部裁切；截图禁用入场动画以捕获稳定通知。几何检查需结合截图人工查看；这些要求不是已经完成的验收结论，也不替代真实读屏、跨浏览器或其他 OS 验证。

证据链接进入实际内容：产物打开 Artifacts 对应记录，门禁日志打开 Gates 对应门禁，审计事件打开 Audit 对应事件，PR 正文、交付包和差异打开 Delivery 对应章节。导航保留当前标签页的认证上下文，并将焦点和视口移到目标。目标不存在、读取失败或被筛选隐藏时说明原因，不能只改变 URL 就表示已找到证据；普通刷新不反复抢走焦点。

5. 演进边界

本设计沿用现有路由、表单、RunControls、服务端领域状态和 Job 机制，不新增调度服务或并行取消状态体系。持续协作与完整导出需要独立产品和技术合同。旧 Cockpit 原型与 Web 架构方案作为历史设计输入，不代表当前界面或权限合同。
