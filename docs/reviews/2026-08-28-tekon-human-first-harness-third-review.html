产品与 UX

已成立：受控交付 Deliver

Web 明确命名“受控交付”，Composer 明示完整角色链路，README/手册披露轻量协作和会话追问尚未开放，PR/远端副作用仍需人工批准。准确结论是：Deliver 合同成立，但不是完整的人类研发工作台。

未关闭：Collaborate

LegacyAgentDriver.events() 等 one-shot 完成后才输出缓冲事件；follow-up、steer、resume 仍抛 NotSupportedYet；多数 assistant 内容仍在完成后由 artifact 合成。用户不能在同 Session 继续输入、转向或重启恢复。

Session 任务中心

行动优先排序、行动徽标和自动变化的相对时间均已改善；但 ticker 只更新文字，不更新 Session 数据。另一个进程产生的新任务或审批仍需刷新。

失败任务缺少确认语义

failed 永远映射为 needsAction，且系统没有 acknowledgedAt/archive/changedSinceSeen。历史失败会永久占据最高优先级。

其他 UX 缺口

  • 完整 Deliver 启动前没有角色、Gate、Provider、权限、网络、超时和成本影响因素预览。
  • Token 仍作为普通用户常驻字符串控件。
  • 产品术语仍偏工程内部，个别空状态中英并列。
  • 长 Session 的 replay、内存和 DOM 仍无有界合同。

证据限制：本轮未重新采集完整产品流程截图，以上为源码、契约、Playwright 与既有截图记录审查，不是全站像素级或屏幕阅读器实测。

P0：仍未关闭

  1. Runtime multi-owner：Web 与 CLI 各自启动 JobRunner，共享 SQLite、Git、worktree、文件和子进程；现有条件写不能 fence 全部副作用。
  2. Shutdown 非 quiescent：最多等待 5 秒后清内存引用，未证明 provider、子进程和 late writes 已停止。
  3. Session Event 非权威 log：dual-write 明确 best-effort，可跳过或失败而不影响主写，不能承担 durable inbox/replay/fork/resume。
  4. Collaborate 缺失：无真实 execution-time streaming、follow-up、steer、resume 与重启恢复。

P1：重要问题

  • Session 列表无 workspace 级实时 summary stream。
  • 失败任务无 acknowledge/archive，可能永久置顶。
  • session.get 为取 timestamp 而读取并解析完整尾事件 payload。
  • Session 列表仍无 cursor/limit/summary projection。
  • 长 Session 无分页、虚拟化、摘要和 context pressure。
  • Token 连接体验与产品词汇仍需收敛。
  • DSH bridge 仍固定旧 headless one-shot 边界，应评估 SDK/ACP。
  • Profile、Automation、Goal、LegacyDriver、dual-write 等横向抽象仍领先于纵向协作闭环。

Harness 对齐判断

官方架构把 Session log 作为模型历史、replay、fork、resume 和 persistence 的来源，并通过一个 inbox 接收输入；官方 persistence 还以 flush 排空到 quiescence。Tekon 当前只实现了观察投影和 durable jobs 的一部分，不能因为事件名称相似就视为已经获得 Harness 生命周期语义。

当前 Harness 还提供 SDK JSON-RPC 与 ACP profiles；2026-08-27 的 0.1.2-alpha.1 补齐 ACP 控制并增强会话 UX。Tekon 应通过 ADR 选择 Provider 层或 Session authority 层，不应长期停留在自建半套 Harness 加 headless one-shot 的中间态。

官方 Safety 仍明确其未经过安全审计，sandbox/approval/permission 不保证隔离；SDK/ACP 迁移也不能替代最小权限和容器/VM 边界。

过度设计判断

系统级问题不是单个模块写得差，而是平台抽象顺序领先于产品闭环。 Profile、Automation、Goal、LegacyAgentDriver、dual-write、DSH ACL 和双 composition root 已承担持续成本，但真实流、第二次输入、durable inbox 和恢复仍不存在。下一里程碑应冻结不能直接服务 Collaborate vertical slice 的横向扩展。

同时，多轮“权威报告 + 报告批注 + CHANGELOG 长篇过程记录”已经形成流程性过度设计。本报告应作为 PR #11 的当前权威入口；后续只维护一份 current decision record 与简短 revision log。

推荐顺序

A · Runtime authoritysingle-owner daemon、客户端化、quiescent shutdown、故障注入。
B · Collaborate真实 streaming、durable inbox、follow-up/steer/cancel/resume、恢复和真实 Provider E2E。
C · 升级到 Deliver模式升级、run plan、权限/成本预览、可靠 link/outbox。
D · Scale & polishsummary/cursor、workspace stream、ack/unread、虚拟化、Token UI、DSH SDK/ACP。

验收清单

  • CLI/Web 默认入口可发现，且诚实说明当前是受控交付。
  • Session 列表按人工行动优先，并展示自动变化的活动时间。
  • 同 Session 可继续输入、转向并在重启后恢复。
  • Provider 输出是执行期真实流。
  • Collaborate 与 Deliver 是明确的不同轨道。

  • DSH 接口重新对齐 SDK/ACP 与官方 Safety。
