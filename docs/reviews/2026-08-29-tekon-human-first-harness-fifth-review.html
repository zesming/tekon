产品与 UX

已成立：Deliver / Goal 边界

默认入口、受控交付文案、人工副作用审批以及 Workflow/Goal/provider policy 已基本一致。dsh-headless 被诚实限制为 Goal one-shot，不再伪装成交付 provider。

未成立：Collaborate

同一 Session 仍不能持续输入、follow-up、steer、resume 或在进程重启后恢复；多数 assistant 内容仍是完成后投影。当前是运行观察与治理界面，不是持续协作工作台。

P0：Runtime 与权威事实链

多 owner

Web 与 CLI 分别启动 JobRunner，却共享 SQLite、Git、worktree、运行目录和子进程。jobs CAS 不能 fence Artifact、Gate、Audit、Delivery 与文件副作用。

非 quiescent shutdown

固定等待后清理进程内状态，不能证明 provider、子进程、listener、Git 和文件写入均已结束，也没有 late-write 故障注入证据。

Event 仍是 projection

Session Event 可以在旧事实成功后 best-effort 失败或被跳过，无法承担权威模型历史、durable inbox、完整 replay/fork/resume。

DeepSeek Harness 最新边界

官方仍将 Harness 标为 developer preview，并明确说明未经过安全审计、sandbox/审批/权限不保证隔离。Tekon 的 experimental 与 fail-closed 姿态正确，但不能据此宣称生产安全。

headless 官方边界仍是一 task、一 final answer、随后退出；限制在 Goal 是正确的。与此同时，官方已经公开 SDK stdio JSON-RPC 与 ACP profile，持续协作不应继续建立在旧 one-shot bridge 上。

事实Tekon 当前状态裁决
官方最新 GitHub prerelease 为 dsh-v0.1.2-alpha.1钉死 0.1.1-rc.2保留 fail-closed；重新做 contract 验证前不盲目 bump。
官方 SDK/ACP 已公开设计注释仍把 headless 当唯一机器边界建立独立 ADR，选择一个真实 Collaborate vertical slice。
网络访问不可视为安全隔离内部 ack 固定为 true，人类无端到端确认事实在 run plan、CLI/Web、snapshot/audit 中闭环。
用户需自行安装 DSH缺精确安装命令和副作用前 preflight增加 provider compatibility/preflight。

过度实现与过度设计

Profile、Automation、Goal、LegacyAgentDriver、dual-write、Provider registry 和两套 Runtime composition 已经形成横向平台，但最基本的“真实流 → durable inbox → follow-up/steer → 重启恢复 → Collaborate→Deliver”仍未闭环。后续应冻结不服务该 vertical slice 的新抽象。

同时，超长 CHANGELOG、多轮“权威报告”和重复批注已成为流程性过度设计。从第五轮开始，current.md 是稳定入口，CHANGELOG 不再追加评审过程。

single-owner daemon + repo lock
→ quiescent shutdown + 故障注入
