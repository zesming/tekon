产品逻辑与 UX

已成立：Deliver / 受控交付

主入口、README 与 Composer 已诚实说明会运行角色、Artifact 与 Gate 链路；PR 创建等远端副作用仍需人工批准。当前 Deliver 合同基本成立。

仍未成立：Collaborate

LegacyAgentDriver.events() 仍在 one-shot 完成后回放缓冲事件，followUp、steer、resume 仍未实现，多数 assistant 内容仍在执行后合成。Session 不能持续输入、转向或在重启后恢复。

重要 UX 缺口

  • 完整 Deliver 启动前没有角色、Gate、Provider、网络、超时与成本影响因素预览。
  • Session 列表无 workspace 级实时数据流；历史失败没有 acknowledge/archive/changedSinceSeen。
  • Token 仍是顶栏常驻字符串控件，主路径仍混用 Session、Profile、Gate、Artifact 等工程术语。
  • 长 Session 的数据、内存和 DOM 无分页、虚拟化、摘要与 context pressure。
  • 高级新建运行的折叠标题仍是可点击 div，缺键盘按钮语义和 aria-expanded。

仍未关闭的 P0

P0-ARCH-01 · Runtime 多 owner

Web 与 CLI 均能启动 JobRunner，共享 SQLite、Git、worktree、运行目录和子进程。jobs 表的 owner/status CAS 无法 fence Node、Artifact、Gate、Audit、Delivery 和文件系统副作用。

P0-ARCH-02 · shutdown 非 quiescent

Runner 最多等待约 5 秒后清理进程内引用，没有证明 provider、子进程、Git/文件写入和 listener 已停止，仍可能发生 late write。

P0-ARCH-03 · Session Event 只是观察投影

旧事实源先成功，Event 再 best-effort 双写；失败不回滚，找不到 Session 会跳过。轻量读取只优化观察面成本，没有改变 authority。

P0-PRODUCT-01 · 持续协作闭环缺失

真实 execution-time streaming、durable inbox、follow-up、steer、resume 和重启恢复均未完成。

过度实现与推荐顺序

Profile policy、Automation/readiness、Goal、LegacyAgentDriver、dual-write、DSH headless ACL 与两套 composition root 已形成较高组合复杂度，但持续协作的最小纵向闭环仍缺失。局部代码质量并非主要失败原因，问题是实现顺序偏横向平台化。

single-owner runtime
→ quiescent shutdown
→ 权威 Session log / durable inbox
→ 真实 Provider streaming
→ follow-up / steer / resume
→ Collaborate → Deliver
→ Session summary / pagination / virtualisation

下一里程碑应冻结不能直接服务 Collaborate vertical slice 的横向扩展。
