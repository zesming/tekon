3. 产品逻辑

成立的部分：Deliver 轨道已经形成真实价值：入口可发现、完整治理链边界诚实、非法模式 fail-fast、dsh 网络确认贯通、Artifact/Gate/review/delivery 与人工副作用控制均有实现和测试。

P0 Collaborate 仍缺失

followUp、steer、resume 仍未实现；没有 durable user input、真实执行期 semantic stream、浏览器/进程恢复和 Collaborate → Deliver 升级。当前 Session 是运行观察与治理界面，不是持续协作产品。

P1 Run plan 不是权威合同

默认入口已 fail-closed，但高级 StartRunForm 在 plan RPC 失败时隐藏预览并继续允许提交。preview 与 run 分别重新加载模板，也没有 plan digest/snapshot 绑定，无法证明用户看到的计划就是实际执行计划。

P1 Web 模板目录与 CLI 不一致

CLI 展示 built-ins + project templates；Web 只扫描 .tekon/workflows。新项目高级表单无法显式选择 README 宣称的内置模板。Web 还使用 YAML 内部 id 作为 selector，而 run/plan 按文件名加载，文件名与 id 不同会产生不可执行选项。

5. Runtime 与数据架构

P0 Multi-owner Runtime

CLI 与 Web 均可持有 JobRunner，共享 SQLite、Git、worktree、Artifact、Audit、文件与子进程。Job owner/lease/CAS 不能 fence 全部副作用。长期方向仍应是 repo-scoped daemon + lock，除非明确选择 active-active 并承担所有领域 fencing。

P0 Shutdown 只部分闭环

active poll、late claim、abort/kill 和 pending drain 已显著改善；但 executor/provider 忽略 AbortSignal 时，最终 Promise.allSettled 可永久等待。服务关闭后的 durable 状态究竟是 cancelled、interrupted 还是 recoverable 也未定义。

P0 Session Event 不是事实源

dual-write 仍吞掉 event append 失败，log 无法保证完整重建上下文，也不适合作为 durable inbox、fork/resume 或 follow-up claim 的权威基础。

P1 引用完整性

session_events、jobs、projection_checkpoints 缺统一 Session 外键和孤儿迁移策略。需要 SQLite table rebuild、旧数据策略与升级/回滚测试，不能只对新库快速加约束。

6. DeepSeek Harness 对齐

将 dsh-headless 限制为 Goal one-shot 仍正确。持续协作应评估官方 SDK stdio JSON-RPC 与 ACP：它们已经提供 Session、prompt、semantic update、cancel、list/resume/close 和更完整生命周期。

Tekon Core 虽拥有 version、help contract、default-config/plugin 三类 probe，但生产 adapter 只执行 version gate；完整 capability preflight 仍主要存在于 fixture/opt-in test。应在创建 durable run 之前完成并缓存 binary/version/flags/profile/credentials 检查。

Harness 官方仍标记为 experimental developer preview，sandbox、审批和权限不能保证隔离；Tekon 的确认 UI 不能替代 OS/container/VM 最小权限。

7. 代码、测试与过度设计

优点

  • Core/CLI/Web/Playwright 分层门禁完整；
  • CAS、owner loss、SSE catch-up、auth scope、teardown 等竞态有确定性测试；
  • 浏览器 retry 不会掩盖 flaky；
  • 并发注释通常解释不变式而不是复述代码。

维护风险

  • 稳定控件文案散落复制，导致一次诚实文案调整击穿多文件；
  • 安装器仍缺自定义目录与多 shell smoke；
  • 用户手册 Markdown/HTML 仍写 Node 18，说明生成链存在漂移；
  • Profile、Automation、Goal、Provider registry、LegacyAgentDriver、dual-write 等横向抽象领先于 Collaborate 纵向闭环。

8. 当前优先级

级别问题
P0single-owner Runtime；shutdown/recovery 持久语义；authoritative Session log/durable inbox；Collaborate vertical slice。
P1权威 run plan；Web template catalog；DSH production preflight；连接 health；长 Session 全链路有界；外键迁移；用户手册 Node 文案；全站可访问性。
P2E2E locator 复用；installer smoke；历史报告/CHANGELOG 决策噪声。

9. 推荐顺序

  1. single-owner daemon、repo lock、durable interrupted/recoverable 与 hard deadline；
  2. 权威 Session log + durable inbox + 外键迁移；
  3. DSH SDK/ACP 真实 semantic streaming vertical slice；
  4. follow-up/steer/cancel/resume 与浏览器/进程恢复；
  5. immutable run-plan snapshot + digest，统一默认/高级入口 fail-closed；
  6. Session summary/cursor/分页/虚拟化、health RPC、统一 template catalog；
  7. 手册生成一致性与全站可访问性专项。

10. 验收结论

  • ✅ Deliver 入口和治理边界基本成立。
  • ✅ dsh 网络确认跨入口贯通。
  • ✅ 失败 ack、workspace 刷新、连接凭据语义和核心可访问性改善。
  • ❌ Collaborate、真实 streaming、follow-up/steer/resume 不存在。
  • ❌ Runtime authority、authoritative log、权威 run plan 和长 Session 全链路有界化未完成。
成熟度表述：Tekon v0.17.0 已形成测试较强、启动与风险边界较透明的实验性受控交付执行与观察基础设施；它尚未完成持续协作产品、单一 Runtime 权威、权威 Session 事实链、权威 run plan 和全链路长会话有界化。
