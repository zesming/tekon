本轮发现并修复的合同断点

  1. CLI dsh 联网确认绕过：Web 有确认，CLI 无参数、无 fail-fast、无审计。现已新增 --acknowledge-unrestricted-network 并落审计。
  2. 默认主入口绕过 run plan：高级页有计划，Session Composer 直接启动完整交付。现已补服务端计划摘要并在失败时阻止主入口启动。
  3. 失败确认代际错误：可预确认非 failed Session，list/get 不一致，新失败可能被旧确认遮蔽。现已统一当前状态语义。
  4. 连接管理是假显式：Token 输入仍会自动应用，“已连接”仅表示字符串存在。现改为草稿 + 显式应用，状态改为“凭据已设置”。
  5. stop/poll 竞态：已经进入的 poll 可在 stop 快照 pending 后 claim/spawn。现追踪 pollTask 并先等待 poll 屏障。
  6. workspace SSE 越界：subscribeAll 把其它 workspace 的事件标成当前 workspace。现按持久 membership 过滤并有反例测试。
  7. 查询键旧数据污染：mode/provider/auth key 切换时短暂返回上一 key 的计划。现把状态与 key/generation 绑定。

架构与数据结论

Runtime authority

Web 与 CLI 仍独立创建 JobRunner，共享 SQLite、Git、worktree、Artifact、Audit 和子进程。jobs CAS 不能 fence 所有文件/Git 副作用。建议 repo-scoped daemon + lock，CLI/Web 客户端化。

Shutdown

明确的 late-claim 竞态已关闭；仍需定义服务关闭时 cancel/interrupted/recoverable 的持久语义，以及 provider 不响应 abort 时的 hard deadline。

Session Event

dual-write 仍是 best-effort 观察投影，不能承担模型历史、durable inbox、完整 replay 与 fork/resume 的唯一事实源。

引用完整性

session_events、jobs、projection_checkpoints 对 Session 无统一外键和孤儿迁移策略，应独立做 SQLite 表重建与老库验证。

UI / UX 结论

  • 高级启动页过密：默认应只展示角色链、控制点、权限/网络和人工确认；phase/node/gate key/毫秒参数放入展开详情。
  • 连接状态要诚实：“凭据已设置”已正确；只有完成服务端 probe 后才能显示“已连接”。
  • 长历史仍无界：EventFeed 只限制 DOM，useSessionStream 仍永久累积全部事件。
  • run plan 不是权威合同：后续应保存 template digest、provider/model、permission/network、timeouts、artifacts、human gates 和 actual adopted plan。

DeepSeek Harness 最新对齐

截至 2026-08-30，官方最新 GitHub prerelease 是 dsh-v0.1.2-alpha.1；Tekon 仍钉死 0.1.1-rc.2。

  • SDK：stdio JSON-RPC，可开 Session、发 prompt，并实时观察 Session event、Agent 状态和 subagent completion。

Profile、Automation、Goal、LegacyAgentDriver、dual-write、DSH probe、两套 Runtime composition 已明显多于已经闭环的持续协作能力。下一阶段应冻结不服务于“真实流 → durable input → follow-up/steer → restart resume → Deliver 升级”的横向抽象。

第五轮报告在声明单一入口后又追加大段代理批注和整改回填，重新制造权威性噪声。本轮只更新 current.md 和第六轮报告，不再扩写 CHANGELOG 或旧报告。
