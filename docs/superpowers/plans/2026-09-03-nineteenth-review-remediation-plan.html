2. 产品与设计细节

2.1 DSH 内置 session telemetry 边界

  • 正式 Run 子进程：保持 envMode: exact 与显式白名单机制。
  • Metadata probe 子进程：保留 PATH、DSH_HOME 等必要运行环境，但显式剥除宿主环境（ambient）中的 DSH_TELEMETRY_MODE 与 DSH_TELEMETRY_OTLP_URL，并固定设置 DSH_TELEMETRY_DISABLED=1。
  • 作用域边界：该策略只作用于 Tekon 启动的 DSH 子进程，绝不修改用户宿主环境中独立运行的 DSH。
  • 合同语义规范化：上游对任意非空 DSH_TELEMETRY_DISABLED 都视为关闭，固定 1 是 Tekon 的规范化表达，不代表宿主环境中的 0 会开启 telemetry。
  • 风险事实澄清：在 alpha.3 中，--version 与 --dump-default-config 为 boot-free，但 --profile headless --help 会进入 profile/plugin boot；无证据表明此前发生外传，但不能用不 boot 排除风险，故 preflight 改动属于纵深防御（defense-in-depth），不表述为已发生的数据外传修复。此外，worktree 中的 .env 凭证回退读取仍是独立安全风险，宿主环境继承不等于凭证隔离。

2.2 Advanced Run 准入与交互

提交门设计为只返回阻断原因的纯状态选择器，不承载 UI 文案或发展为通用 DSL。阻断优先级固定为：

no-token
> submitting
> plan-loading
> plan-error
> no-plan
> no-demand
> draft-not-ready
> missing-plan-digest
> network-unacknowledged
  • 交互与文案分层：组件继续使用既有中文提示和 plan error/digest 重试 UI。空需求的初始状态只禁用按钮，不主动显示警告；若发生程序化绕过，仍由 handler 弹出防御性提示。
  • 同步防重入保护：采用同步 useRef latch：在所有校验通过后、调用 mutation 前同步置位，并在 finally 块中释放。React 的 isPending 仅负责视觉交互与按钮禁用，无法在 JavaScript 异步事件循环的微任务前独立保证同一 tick 的 single-flight。

2.3 project.clean 分拆

  • Issue #33 职责：仅负责在完整生命周期方案前关闭活动期误删入口，首选暂停所有物理删除。即使认证、confirm、格式与 scope 校验均通过，也暂停物理删除，并在返回拒绝前写入不含 token 的 Audit；未认证、非法或越权请求不向目标 Run 写 Audit。
  • 边界划定：Issue #33 不宣称 lifecycle-safe。完整 export、compaction、retention、tombstone、路径修正和事务/补偿机制仍然归属 Issue #18。

3. 实现细节

3.1 Core

  • dsh-bridge-probe.ts：在 runDshPreflight() 入口构造一次 inherited-minus-telemetry 环境快照。
  • 默认 probe 复用：三个默认 probe（help、version、config）复用同一环境快照；自定义 probe 继续自行负责环境注入。
  • 测试 seam 隔离：probeEnvSource 仅作为程序化测试 seam 暴露，不接入 CLI、RPC 或 Provider registry。
  • dsh-headless-adapter.ts：不改变生产运行行为，仅补充宿主环境下的 DSH_TELEMETRY_DISABLED=0 被固定为 1 的回归断言。

3.2 Web

  • 纯状态选择器：新增小型 startRunSubmitState() 纯函数与表驱动单测（packages/web/__tests__/client/start-run-submit-state.test.ts）。
  • 表单组件集成：StartRunForm（packages/web/src/client/components/runs/StartRunForm.tsx）使用该函数计算 disabled 状态与 reason，并增加同步 in-flight latch 防重入。
  • 规范化 e2e 测试：新增合规命名的 packages/web/__tests__/e2e/start-run-admission.e2e.test.ts，先证明无 latch 时能观察到两个 project.run 请求，再验证修复后只有一个。
  • 匹配精度提升：现有 digest e2e（packages/web/__tests__/e2e/start-run-form.test.ts）的响应匹配收窄到 RPC body 中 path === 'project.run'，避免被并发或预检请求干扰。
  • 窄屏视觉收敛：真实浏览器验收发现 390px/700px 选择器文本被裁切后，新增 RED→GREEN e2e；768px 及以下使用单列选择器，闭合标签保持简短，完整风险与自动化边界保留在相邻帮助中。

4. 测试先行顺序

所有改动遵循严格的测试先行与可证伪原则：

  1. Core 环境继承证伪（RED）：先新增 Core fake DSH 环境测试，确认现状会继承宿主 telemetry 配置并断言失败。
  2. Web 选择器单测先红（RED）：先新增 Web start-run-submit-state.test.ts 单测，确认模块缺失而失败。
  3. Web 并发双发证伪（RED）：先新增重复提交 e2e（packages/web/__tests__/e2e/start-run-admission.e2e.test.ts），稳定观察到两个 project.run 请求后再实施 latch 保护。
  4. 功能实现转绿（GREEN）：实现 Core 环境裁剪与 Web 状态选择器 + latch，使上述测试全部转绿。
  5. 定向回归套件验证：运行相关 Core 单元测试与 Web e2e 测试套件。
  6. 第一批全量门禁与视觉检查：第一批交付（代码、测试、手册、CHANGELOG 与版本号）就绪后执行全量类型检查、代码检查、构建验证与视觉检查。
  7. 第二批再次验证：第二批交付（复审报告 Markdown/HTML、current.md 与 PR 元数据）完成后执行 pnpm test 与相关门禁再次验证。
  8. 独立 Reviewer 双轮复核：代码/测试、技术文档、文字编辑和报告完成度分别交独立 reviewer 复核。
